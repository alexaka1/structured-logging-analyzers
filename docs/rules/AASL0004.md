# AASL0004: Incorrect type is used for contextual logger

Use the containing type as the context type. The diagnostic points at the
`ILogger<T>` type usage or the `ForContext<T>()` invocation.

**Noncompliant**

```csharp
class Orders
{
    public Orders(ILogger<Users> log) { }
    private static readonly ILogger Log = Logger.ForContext<Users>();
}
```

```csharp
class Orders(ILogger<Users> log) { }
```

**Compliant**

```csharp
class Orders
{
    public Orders(ILogger<Orders> log) { }
    private static readonly ILogger Log = Logger.ForContext<Orders>();
}
```

```csharp
class Orders(ILogger<Orders> log) { }
```

Primary constructors are analyzed.
Unresolved or open generic type arguments are not reported. The analyzer waits
until the compiler can identify the category or `ForContext<T>` type.

Conditional-access calls such as `logger?.ForContext<Users>()` are analyzed as
well. The `ForContext<T>()` type-argument fix is offered for direct member
access calls; conditional-access diagnostics remain safe to leave unchanged.

Code fix: replace `T` with the containing type. For `ILogger<T>` declarations,
the fix also updates matching primary-constructor parameters, constructor
parameters, fields, and properties on that type. `ForContext<T>()` only
rewrites the type argument on that call. Nested types are left alone.
