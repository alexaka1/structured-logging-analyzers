# AASL0009: Template property naming

Named holes must match the configured naming convention and must not be
ignored by regex. The default convention is PascalCase. The diagnostic
points at the hole.

**Noncompliant**

```csharp
Log.Information("{userId}", id);
```

**Compliant**

```csharp
Log.Information("{UserId}", id);
```

Configure with `dotnet_code_quality.AASL.property_naming` and
`dotnet_code_quality.AASL.ignored_properties_regex`. Values:
`pascal_case` (default), `camel_case`, `snake_case`, `elastic_naming`,
and `semantic_conventions` (alias `semconv`).

[Semantic Conventions](https://opentelemetry.io/docs/specs/semconv/general/naming/)
use dotted lowercase names with underscores inside a component:

**Noncompliant** (`semantic_conventions`)

```csharp
Log.Information("{OrderId}", id); // suggested `order_id`
```

**Compliant** (`semantic_conventions`)

```csharp
Log.Information("{service.name}", name);
Log.Information("{http.response.status_code}", 200);
```

The same options can be scoped to this rule as
`dotnet_code_quality.AASL0009.property_naming` and
`dotnet_code_quality.AASL0009.ignored_properties_regex`.
The rule-scoped key wins. The prefix-level key applies when there is no valid
rule-scoped value. Invalid values are ignored and fall through to the next
level, then to the built-in default.

A digit followed by an uppercase letter starts a new word. For example,
`Utf8Bytes` remains PascalCase and becomes `utf8_bytes` in snake_case.
Letter-to-digit pairs stay together. The rule does not report a name when its
suggestion would be positional, because that rewrite would change the hole's
meaning.

Also reported on `[LoggerMessage]` attribute strings and
`LoggerMessage.Define` / `DefineScope` format strings, and custom methods marked
with an attribute named `MessageTemplateFormatMethodAttribute`. A custom
attribute declared in the project is recognized without a logging-library
reference. A code fix rewrites the attribute string, including exclusive
private `const` messages on the same type and syntax tree.
Constant interpolated text is analyzed from its runtime value, so escaped
template holes such as `$"user {{user_id}}"` are checked as `{user_id}`.
The fix is withheld when the source cannot be mapped exactly or a constant is
non-private, shared, or declared in another syntax tree. This includes
constant `[LoggerMessage]` expressions such as `$"{Shared}"`. Unmappable and
cross-tree diagnostics point at the attribute argument instead.

When `semantic_conventions` is configured, AASL0012 (generated logging cannot
use Semantic Conventions property names) also warns on `[LoggerMessage]`.
AASL0009 still only checks hole names. `LoggerMessage.Define` / `DefineScope`
are not reported by AASL0012.
