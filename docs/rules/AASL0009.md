# AASL0009: Template property naming

ReSharper ID: `InconsistentLogPropertyNaming`

Default convention is PascalCase.

```csharp
Log.Information("{userId}", id);   // noncompliant
Log.Information("{UserId}", id);   // compliant
```

Configure with `dotnet_code_quality.AASL.property_naming` and
`dotnet_code_quality.AASL.ignored_properties_regex`. Values:
`pascal_case` (default), `camel_case`, `snake_case`, `elastic_naming`,
and `semantic_conventions` (alias `semconv`).

[Semantic Conventions](https://opentelemetry.io/docs/specs/semconv/general/naming/)
use dotted lowercase names with underscores inside a component:

```csharp
Log.Information("{service.name}", name);             // compliant with semantic_conventions
Log.Information("{http.response.status_code}", 200); // compliant with semantic_conventions
Log.Information("{OrderId}", id);                    // noncompliant; suggested `order_id`
```

The same options can be scoped to this rule as
`dotnet_code_quality.AASL0009.property_naming` and
`dotnet_code_quality.AASL0009.ignored_properties_regex`.

Also reported on `[LoggerMessage]` attribute strings and
`LoggerMessage.Define` / `DefineScope` format strings. A code fix rewrites
the attribute string, including exclusive `const` messages on the same type.

When `semantic_conventions` is configured, AASL0012 (generated logging cannot
use Semantic Conventions property names) also warns on `[LoggerMessage]` and
`LoggerMessage.Define` / `DefineScope`. AASL0009 still only checks hole names.
