# AASL0012: Generated logging cannot use Semantic Conventions property names

No ReSharper ID. This rule is not in the original plugin.

When template property naming (`AASL0009`) is set to `semantic_conventions`,
`[LoggerMessage]` and `LoggerMessage.Define` / `DefineScope` cannot use those
names. The generator binds `{holes}` to C# parameter names, and parameter
names cannot contain `.`.

```csharp
[LoggerMessage(Message = "Call {http.request.method}")] // noncompliant
public static partial void RequestStarted(ILogger logger, string method);
```

```editorconfig
dotnet_code_quality.AASL.property_naming = semantic_conventions
```

AASL0009 (template property naming) is unchanged. It still checks hole names
on those templates. This rule only warns that generated logging is the wrong
API for that style.

Use Serilog, NLog, or MEL `Log*` templates for dotted names, or keep identifier
holes on `LoggerMessage` and set dotted names with `LogContext.PushProperty`
(`AASL0010`, context property naming).

Does not report when `property_naming` is PascalCase, camelCase, snake_case,
or Elastic, or when only `AASL0010` is scoped to `semantic_conventions`.
