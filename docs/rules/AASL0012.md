# AASL0012: Generated logging cannot use Semantic Conventions property names

When template property naming (`AASL0009`) is set to `semantic_conventions`,
this rule reports on `[LoggerMessage]` only if a parsed named hole's Semantic
Conventions suggestion contains `.`. The generator binds `{holes}` to C#
parameter names, which cannot contain `.`. The diagnostic points at the
attribute name and reports at most once per method.

```editorconfig
dotnet_code_quality.AASL.property_naming = semantic_conventions
```

**Noncompliant**

```csharp
[LoggerMessage(Message = "Call {http.request.method}")]
public static partial void RequestStarted(ILogger logger, string method);
```

Already-valid dotted names such as `http.request.method` still report because
their suggestion is the name itself. A name such as `Http.RequestMethod`
also reports because its suggestion is `http.request_method`.

**Compliant**

```csharp
[LoggerMessage(Level = LogLevel.Information, Message = "Started")]
public static partial void Started(ILogger logger);

[LoggerMessage(Level = LogLevel.Information, Message = "Count {count}")]
public static partial void Counted(ILogger logger, int count);

// Dotted names can use positional binding instead.
logger.LogInformation("Call {http.request.method}", method);

private static readonly Action<ILogger, string, Exception?> RequestStarted =
    LoggerMessage.Define<string>(
        LogLevel.Information,
        new EventId(1, nameof(RequestStarted)),
        "Call {http.request.method}");
```

Hole-less templates and names whose suggestions contain no dot do not report
AASL0012. For example, `{userId}` suggests `user_id` and `{HttpRequestMethod}`
suggests `http_request_method`. AASL0009 still reports those naming mismatches.
Holes matching special logger, level, or exception parameters are skipped,
just as they are for the other named-template rules. An unresolved message
that cannot be parsed does not report AASL0012.

`LoggerMessage.Define` and `DefineScope` bind values by position. Dotted
template names can work there, so this rule does not report them.

Does not report when `property_naming` is PascalCase, camelCase, snake_case,
or Elastic, or when only `AASL0010` is scoped to `semantic_conventions`.

No code fix. Keeping dotted property names requires choosing a logging API
such as `LoggerMessage.Define` or a `Log*` call. Keeping `[LoggerMessage]`
requires identifier-compatible hole names that match its parameters. Neither
change is safe to choose automatically.
