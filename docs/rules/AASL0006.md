# AASL0006: Duplicate properties in message template

Two or more named holes must not use the same property name. The diagnostic
points at each duplicate hole. Positional-only templates are not reported.

**Noncompliant**

```csharp
Log.Information("{Id} {Id}", a, b);
```

**Compliant**

```csharp
Log.Information("{Id} {Name}", a, b);
```

Also reported on `[LoggerMessage]` when two holes use the exact same name.
Names that differ only by case are left to SYSLIB1021.

Code fix (invocations): rename duplicate holes to unique names. The first
occurrence is kept when it is already unique after other holes are renamed;
later holes become `Name2` or a name derived from the aligned argument
(`orderId` → `{OrderId}`). Leaf and qualified argument names share one
primary-name set so Fix All cannot assign the same name to two holes.
Qualified names are a second action when they differ. Not offered on
`[LoggerMessage]`: renaming a hole would not add a matching C# parameter.
As with the other template rewrites, the fix is withheld when a constant
field or concatenated template cannot be mapped to exact source text.
