# AASL0002: Complex objects should be destructured

Complex objects whose inherited `ToString()` is `Object.ToString()` should
usually be destructured or stringified. The diagnostic points at the hole.

**Noncompliant**

```csharp
class User
{
    public int Age { get; set; }
}

Log.Information("The user is {User}", new User());
```

**Compliant**

```csharp
class User
{
    public int Age { get; set; }
}

Log.Information("The user is {@User}", new User());

// or

Log.Information("The user is {$User}", new User());
```

Not reported when the hole already uses `@` or `$`, or when the argument type
is classified as having an adequate `ToString()`.

A trailing empty format does not remove a hole from argument alignment, so
`{User:}` and `{User,10:}` are checked like `{User}`.

Elements written in an explicit `params` array are checked individually.
This includes C# collection expressions such as `[first, second]`; collection
expressions with spread elements are left unanalyzed because hole alignment is
not statically fixed.

Code fix: insert `@` into the template hole when the template has an exact
source mapping. A diagnostic is still reported for an unmappable constant
field or concatenation, but no rewrite is offered.

Not applied to Microsoft.Extensions.Logging `Log*` calls, ZLogger, or
`LoggerMessage.Define` / `DefineScope`. Those templates do not use Serilog's
`@` operator.
