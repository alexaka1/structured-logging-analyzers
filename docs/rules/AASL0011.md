# AASL0011: Log event messages should be fragments, not sentences

The last constant template fragment must not end with a single period. The
diagnostic points at the trailing period.

**Noncompliant**

```csharp
Log.Information("Hello {Name}.", name);
```

**Compliant**

```csharp
Log.Information("Hello {Name}", name);
Log.Information("Loading {Name}...", name); // ellipsis is allowed
```

Ellipses (`...`) are not reported.

Code fix: remove the trailing period. Non-private, shared, and cross-tree
`const` messages still warn, but the fix is withheld unless the constant is
private, exclusive to the logging method, declared in the same syntax tree,
and the diagnostic span contains exactly one source `.` character.
Constant interpolated text is mapped from its runtime value, so the fix can
remove a period from `$"Operation done."` without replacing the whole string.
Unmappable fields and concatenated constant fragments remain diagnostic-only.
When the last operand is an unmappable constant identifier, the diagnostic
points at that identifier if the complete constant template ends in one
period. No fix is offered for that form.

Also reported on `[LoggerMessage]` attribute strings and
`LoggerMessage.Define` / `DefineScope` format strings.
Unmappable and cross-tree constant attribute expressions still report on the
attribute argument without a fix. ZLogger 1.x `format` and `message` overloads
are both checked.
