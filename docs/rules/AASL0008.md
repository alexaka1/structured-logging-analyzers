# AASL0008: Prefer named properties instead of positional ones

```csharp
Log.Information("{0}", id);     // noncompliant
Log.Information("{Id}", id);    // compliant
```

Mixed positional/named templates do not report this diagnostic.

A code fix renames a positional hole when a name can be derived safely:

- Logging invocations: from the aligned argument expression when it has an
  identifier (`orderId` → `{OrderId}`, `order.Id` → `{Id}`). A second action
  uses qualified names when they differ (`{OrderId}`). Literals, anonymous
  objects, and a params array passed as a single variable are left unchanged.
- `[LoggerMessage]`: from the matching template parameter when the remaining
  parameters (after the first logger, level, and exception) line up with the
  positional holes.

`LoggerMessage.Define` / `DefineScope` still report the diagnostic and have no
rename: values are supplied later, so there is no identifier at the call.
